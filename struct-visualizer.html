    Packed. In a struct packed the members are laid down without gaps and the first member specified is the most significant, so bit 0 of the vector is the last bit of the last member. Members must be integral: a real, an unpacked array or a plain struct inside one is flagged.

    Plain. A struct with no packed keyword gives every member a whole word of its own — 8, 16, 32 or 64 bits, whichever unpacked align to says — and the spare bits appear as pad. Field sits at puts the member against the top of that word or against the bottom; at the bottom its least significant bit lands on the boundary, the way a register map usually reads. A member wider than the word takes as many words as it needs. The structure itself is rounded up to whole words, so nesting one inside another keeps the alignment, and a packed member abuts its own fields inside whatever word it lands in.

    Reading the diagram. Bit 0 sits at the right of the last row, tick marks step one bit each with a longer mark on every byte boundary, and each field carries the bit index of its own two ends. A field wider than the row is drawn on both rows with a dotted edge where it continues. Copy image puts a PNG of the rows as drawn, at three times the size on screen, on the clipboard — or saves it as a file if the browser will not take a picture.

    Two syntaxes. Source syntax says which language the box holds. On SystemVerilog the last tab writes SystemRDL; on SystemRDL it writes SystemVerilog, and the RDL is read by laying its registers end to end with offset 0 at the bottom — the same order it is written out in — so the diagram, the table, C and Python all work the same either way. Switching the setting puts whatever that tab was showing into the box, so the two directions are a round trip. A SystemRDL field cannot hold fields, so a nested struct travels as a dotted desc — ctrl.cmd — and reading it back turns each run of name.field descriptions into the subtype it came from, with its own typedef when flatten is off. A description that starts with an underscore, at any level, is read as reserved, so ctrl._rsvd stays quiet under the underscore switch. A description that reads like prose is left as documentation and the instance name is used instead. One thing does change on the way through: the vector grows to hold whole registers, so 48 bits in 32-bit registers comes back as 64 with the spare bits reserved. Bits no field claimed arrive as _rsvd members.

    What the parser reads. typedef, struct and union bodies, packed and unpacked dimensions, parameter, localparam and `define values in range expressions, plus $bits and $clog2. Everything else in the file is skipped, and any line it could not read, or had a word of warning about, is marked in the line numbers.

    Generated code. The C and Python tabs move the same bit positions the diagram draws. Up to 64 bits the C carries the vector in one unsigned word; wider than that it uses a byte array with buf[0] holding the first member, the order the rows read from the top down. Python integers have no width limit, so one shift and mask serves any size. Field paths become identifiers — slot[3].lo turns into slot_3_lo — and pad bits are left at zero.

    Nested types. With flatten off a nested struct stays one block in the diagram, and the generated code keeps it as its own type: C gets a nested struct with its own pack and unpack that the outer one calls, Python gets a nested dataclass held by field(default_factory=...), and SystemRDL — where a field cannot hold fields — gets a reg component describing the inside, which the carrying field points at. Bit numbers inside a nested type start again from its own bit 0. Two members of the same type share one description. C keeps a nested struct wider than 64 bits as a byte array instead, since its pack has no single word to return; Python has no such limit.

    SystemRDL. Each type becomes an addrmap of registers RDL register width bits wide, so a type larger than one register is spread over as many as it needs. Registers are listed in address order, and offset 0 carries the least significant word, so bit 0 of the struct is bit 0 of the first register — the opposite end from the diagram, which puts the first member at the top. A field that crosses a register boundary is split into parts named after the bits of the field they hold, and the low part lands at the low address: addr[7:0] becomes addr_7_0 at offset 0, addr[31:8] becomes addr_31_8 in the next register. Bits no field claims are left undeclared, which SystemRDL reads as reserved, and sw and hw access are set once as addrmap defaults for you to change.

    Fields held back. Turning off show _names also drops those fields from the generated struct, dataclass and addrmap. They are treated like pad from then on: pack leaves their bits at zero, unpack does not read them back, and no register field is declared for them. The ranges it left out are named in the comment at the top of each tab, and the field table still lists them so you can see what is in the gaps.
