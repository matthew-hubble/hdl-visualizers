Reading the map. The registers are laid end to end with offset 0 at the bottom, so bit 0 of the register at offset 0 is bit 0 of the vector. The diagram reads the other way round, highest bits at the top, one row per word; tick marks step one bit each with a longer mark on every byte boundary, each field carries the bit index of its own two ends, and a field wider than the row is drawn on both rows with a dotted edge where it continues. The value at the end of a row is what that word of the vector holds.
Which component. Component to draw offers every component the source names — an addrmap, a regfile or a reg — and under each map the registers it holds, each at the address it sits at. A register drawn on its own is drawn as its own vector, numbered from its bit 0 rather than from the bottom of the map, which is how its own documentation would have it; the address is repeated under the layout. A source that has just changed opens on the outermost component rather than on one of its registers, and every element of an array of registers is offered separately, at the address its stride puts it at.
Reserved. Bits that no field claims come back as _rsvd members, and show _rsvd decides whether they are named in the diagram and listed in the tables below. It starts off, since a register map is read by its fields, but their bits belong to the vector either way: they are drawn in the layout, and the whole-vector value covers them whether they are listed or not.
Values. A hex box takes a bit pattern: hex 0x, binary 0b, octal 0o or plain decimal, with underscores and spaces ignored. Every field has one, in both tables, and so does the whole vector, and each writes only the bits it owns. A pattern too wide for the field it lands in is masked to the bits it has, the way the hardware would take it, and a negative decimal is read as two's complement. zeros, ones and random set the whole vector at once. The page opens on a fixed pattern, so there is something to read before you type.
Reading them back. Each field is read as whatever its own read as says, so a coefficient can be fixed point in the same register as an integer count, and the vector itself takes the last row and reads the same way. Signed puts a two's complement sign bit on top of the field; a float carries its own sign, so the box is held for one. Q format takes the TI form Qm.n: n fraction bits, m integer bits, and the sign bit above them when there is one, which is why m follows the width and the sign on its own. A format whose bits do not add up to the width of the field is marked, and the value is still read with the n it asked for.
Which floats. A field is offered the formats that are its width, named outright rather than as one float among them: binary16 and bf16 at sixteen bits, binary32 at thirty-two, binary64 at sixty-four, the OCP eight-bit pair E4M3 and E5M2, and the four-bit pair E2M1 and E3M0. A field of any other width is offered no float at all. Where a width carries two, the one it opens on is the IEEE format if there is one and the commoner of the two if there is not.
What a float keeps back. IEEE 754 spends its top exponent on the infinities and the NaNs, and E5M2 follows it. E4M3 keeps back only the one word with every significand bit set, so its top exponent still counts up to 448. The four-bit formats keep nothing back: E2M1 runs to 6 and E3M0 to 16, and since neither has an infinity or a NaN there is nothing for a box to take when one is asked of it. A value past the end of a format becomes an infinity where the format has one and stops at its largest word where it does not.
A comment says what a field is. A comment after the semicolon that ends a field says how to read it: signed, unsigned, a TI Q format such as Q1.14 or UQ2.14, or a float — float for whichever format fits the field, or one named outright, as BF16, binary16, FP8 (E4M3), FP8 (E5M2), FP4 (E2M1), FP4 (E3M0), or any EeMm shape one of those comes in. Either kind of comment carries it, and words the page does not know are passed over, so prose beside a field is not read as a type. A format that does not fit the field it sits beside is said out loud rather than used. Every element of an array of registers takes the comment written once in the component. Changing a comment moves that field to what it now says; changing a box by hand holds until the comment itself changes.
Values in a type. The value box takes what its type reads — a whole number, a decimal for fixed point, or a decimal, inf or nan for a float. Unlike a bit pattern, a value out of range saturates at the nearest end of what the field holds rather than wrapping; a fixed point one is rounded to the nearest word with ties away from zero, and a float to nearest with ties to even, the way IEEE 754 asks. Every value is worked out in exact integer arithmetic and printed exactly wherever that is short enough to read; a longer one is printed to the seventeen significant digits that pin down a double, and either form typed back gives the same bits.
What the parser reads. addrmap, regfile and reg components, named or anonymous, with their fields at an explicit bit range — [11:4] — or given a width, [8], which SystemRDL packs from bit 0 upwards in the order they are declared, plus regwidth, @ offsets, += strides and array counts. A field whose desc reads like prose keeps its instance name; one that reads name.field is taken as a path, and a run of them becomes the structure it came from. Everything else in the file is skipped, and any line it could not read is marked in the line numbers. Two fields that would land on one name take their register's name with them, so chan[4] comes back as chan_0_burst and its three siblings.
The other direction. struct-visualizer.html starts from a SystemVerilog struct packed and writes the SystemRDL, C and Python for it. Both pages read a register map the same way, so an addrmap moves between them unchanged.
